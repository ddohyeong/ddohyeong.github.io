네트워크를 공부하면 모델이 두 개 나온다. OSI 7계층과 TCP/IP 4계층. 둘 다 계층으로 네트워크를 설명하는데, 왜 두 개가 필요한지는 아무도 설명해 주지 않는다. 이 글은 그 질문에 대한 정리다.

![OSI와 TCP/IP 계층 비교](attachments/osi-tcpip.svg)

## 1. 두 모델

### 1.1 OSI 7계층

Open System Interconnection. 네트워크 통신 기능을 7개 계층으로 나눈 개념적 프레임워크다.

| 계층  | 이름     | 역할                          |
| --- | ------ | --------------------------- |
| 7   | 응용     | 사용자와 가장 가까운 단계. 화면이나 메뉴를 제공 |
| 6   | 표현     | 데이터를 읽기 편하게 변환하고 압축하거나 암호화  |
| 5   | 세션     | 컴퓨터 사이의 대화와 연결 상태를 유지       |
| 4   | 전송     | 데이터를 잘게 나눠 안전하게 보내고 도착을 확인  |
| 3   | 네트워크   | 목적지까지 가장 빠른 길을 찾아 전달        |
| 2   | 데이터 링크 | 가까운 기기 사이에 오류 없이 신호를 전달     |
| 1   | 물리     | 전선이나 전파로 0과 1의 전기 신호를 주고받음  |

### 1.2 TCP/IP 4계층

인터넷이 **실제로** 동작하는 방식을 4개 층으로 서술한 모델이다.

| 계층 | 역할 | OSI 대응 |
|---|---|---|
| 응용 | 프로그램끼리 주고받을 데이터의 형식과 절차를 정함 | 5·6·7 통합 |
| 전송 | 상대 컴퓨터의 특정 프로그램까지 전달하고 도착을 확인 | 4 |
| 인터넷 | 여러 네트워크를 건너 목적지까지 갈 길을 찾음 | 3 |
| 네트워크 접근 | 바로 옆 기기까지 신호로 바꿔 오류 없이 전달 | 1·2 통합 |

## 2. 왜 두 개인가

### 2.1 만들어진 방향이 반대다

이게 핵심이다.

- **OSI는 규범적 모델이다.** 모델을 먼저 서술하고 그에 맞춰 프로토콜을 구현하려 했다.
- **TCP/IP는 서술적 모델이다.** 이미 돌아가던 프로토콜을 사후에 정리했다.

TCP/IP가 먼저 나왔고, 이미 동작하고 있었다. 나중에 나온 OSI는 프로토콜 경쟁에서는 밀렸지만 **모델과 용어는 살아남았다.** OSI 규격대로 구현된 프로토콜도 존재하긴 했으나, 이미 자리를 잡은 TCP/IP를 밀어내지 못했다.

TCP/IP 모델이 사후 정리라서 계층 경계가 모호한 것도 이 때문이다. 그래서 4계층 대신 5계층으로 설명하는 자료도 있다.

### 2.2 역할이 다르다

한 줄로 정리하면 이렇다.

> **OSI는 말하기 위한 것, TCP/IP는 돌아가는 것.**

OSI는 **자(尺)**에 가깝다. 패킷의 어느 지점을 가리키기 위한 눈금이다. 7개로 촘촘하고 번호가 명확해서 지시하기 좋다. "L4 로드밸런서", "L7 방화벽", "L2 스위치" — 전부 위치를 가리키는 좌표다. 대신 이 자로 잰다고 뭐가 만들어지지는 않는다.

TCP/IP는 **실제 지형**이다. 지금 돌아가는 프로토콜들과 그것들이 실제로 쌓여 있는 방식. 4계층이라는 건 그 지형을 대충 그린 약도지 지형 자체가 아니다.

실무에서 둘을 섞어 쓰는 게 이상한 게 아니라, 그게 표준이다.

## 3. 캡슐화 — 계층이 실제로 작동하는 방식

### 3.1 각 계층은 위에서 받은 데이터를 열어보지 않는다

계층화의 핵심 규칙이다. 각 계층은 위에서 받은 데이터를 **파싱하지 않고**, 자기가 관리하는 정보로 자기 헤더를 만들어 앞에 붙인다.

헤더는 각 계층이 직접 조립한다. 앱이 만들어서 내려보내는 게 아니다. 값의 출처는 세 가지다.

- **앱이 지정** — 목적지 IP, 포트
- **그 계층의 상태** — 시퀀스 번호, 윈도우 크기
- **외부 조회** — 라우팅 테이블, ARP 캐시(다음 홉 MAC)

### 3.2 다음 계층을 지시하는 필드

역캡슐화는 마법이 아니라 단서를 따라가는 과정이다. 각 헤더에는 다음이 무엇인지 알려주는 필드가 있다.

```
EtherType 0x0800  →  "다음은 IP"
IP Protocol 6     →  "다음은 TCP"
TCP 목적지 포트    →  "이 소켓으로"
```

### 3.3 실제 구현은 데이터를 떼어내지 않는다

교과서 그림은 계층을 지날 때마다 헤더가 하나씩 벗겨지는 것처럼 그린다. 실제 구현은 다르다.

리눅스 커널은 `sk_buff` 하나에서 **포인터만 이동시킨다.** 헤더는 메모리에 그대로 남아 있다. TCP 체크섬을 검증할 때 IP 헤더를 다시 참조해야 하기 때문이다. 패킷이 물리적으로 잘려나가는 게 아니다.

## 4. 정리

TCP/IP가 먼저 나와 자리를 잡았고, 나중에 나온 OSI는 프로토콜로는 졌지만 어휘로는 살아남았다. 그래서 지금 우리는 **말할 때는 OSI 번호를 쓰고, 실제 동작을 설명할 때는 TCP/IP를 쓴다.** 두 모델을 같이 봐야 하는 이유가 이것이다.
